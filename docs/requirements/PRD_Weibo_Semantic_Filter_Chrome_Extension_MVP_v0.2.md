# PRD — 微博语义过滤 Chrome 扩展

更新：2026-09-22。需求基线 **v0.2 + 用户已确认补充**，对应当前实现 0.3.3。保留原文件名，便于已有引用继续使用。本文已纳入体育、纯图片、人物规则、其他账号直接折叠和反馈交互调整，取代原文中的「两账号全部保留」「不支持任何看图」等旧边界。

当前已交付可安装扩展及语义连接；不代表真实中文或图片分类效果已全部验收。操作见[指南](../guides/weibo-extension.md)，实现契约见[架构](../architecture/weibo-semantic-filter-mvp.md)。

## 1. 产品目标与形态

用户在原生微博网页阅读，通过个人 Chrome Manifest V3 扩展减少不想看的体育、指定人物、无信息风景照片，以及按账号区分的纯互动、哲理、鸡汤和诗词。保留原生页面与可恢复的原内容，不再建设抓取服务、数据库服务或独立阅读器。

交付源码、可加载 `dist/`、版本化 ZIP、设置页和 popup、测试与人工评估工具、使用文档。浏览器本地保存设置、缓存和反馈；不设置自有服务器。

## 2. 产品原则

- 原网页增强，不重建 feed，不获取尚未渲染的内容。
- 模型只返回分数或结构化判断，是否折叠由代码决定。
- 模型超时、格式错误、信息不足或 DOM 无法可靠识别时保留原内容。
- 明确的用户通用过滤规则优先于旧账号保护；其余账号策略保守处理，实质信息优先保留。
- 默认 Shadow；用户可自行切换 Active。所有折叠都可展开。
- 反馈可用于后续人工评估，但不自动训练模型或更新规则。

## 3. 范围

包括首页、分组页、账号页动态卡片；四账号开关；本地人物/短互动规则；Jev 文字语义；可选图片识别；正常/灰化/折叠；原因和分数；单条及本页展开；设置、缓存、纠错与导出；SPA 导航和异常降级。

不包括微博 API 抓取、定时同步、历史回填、自有服务器、独立阅读页面、手机 App、跨设备同步、自动摘要或投资结论、聚类、完整线程重建、未渲染评论/回复、在线学习、商店上架、视频识别及转写。图片能力只限下述完整配图的保守分类，不承诺通用 OCR 或人物识别。

### 四账号共同规则

1. **指定人物**：正文或转发原文明确提到林园、董宝珍（含繁体），本地建议折叠，无需 API。即使含价值投资内容也适用；正文只展示了一部分，但已经出现姓名时也可命中。未写姓名或姓名只在图片里时不推断。
2. **体育**：主要内容涉及篮球、足球、高尔夫等体育运动、赛事、运动员或个人打球，Jev 高置信命中时建议折叠；仅借用体育比喻的其他主题不应命中。
3. **无实质文字的图片**：仅在用户单独开启看图后，识别纯风景照片及无字高尔夫等体育照片。问候、地点、日期、打卡、emoji、简单赞叹不算实质文字。图表、财报、文字截图、混合内容、不完整或看不清的图片保持原样。

规则在设置中可独立开关，默认共同规则开启、图片识别关闭。看图使用同一 Vercel key 并产生额外用量；最多 9 张完整配图，不处理视频画面。

## 5. 交互

- Shadow：四个目标账号的自动判断只显示「建议折叠／建议灰化」；其他账号按独立开关直接折叠，显示「已折叠」而不是建议。
- Active：自动执行折叠或灰化，显示可展开控件。
- 「应保留／应折叠」：在两种模式下均立即展开或折叠本条，并显示保存成功或失败提示。选择在当前文档会话内有效，刷新后按规则重判。
- 「展开」仅为阅读操作，不自动记录误判。
- 「本页全部展开」恢复内容并暂停当前路由后续展示变化；重新扫描不能解除暂停。
- 关闭功能恢复原卡片；管理页重载、禁用或卸载后需刷新微博。
- 所有卡片均显示结果或处理状态：等待、判断中、保留、折叠或灰化。无法识别和连接失败有明确提示并保留内容，关闭过滤或暂停时移除标签。

设置包含运行模式、账号开关、共同规则、图片识别授权、Jev 连接、超时、词表、阈值、可选原文采样、缓存清除及反馈导出。连接测试用固定文字，不包含真实微博，也不代表看图连接或准确率通过。

## 6. 数据、权限与反馈闭环

API key 仅存扩展可信上下文，输入框遮蔽，不返回 content script、不写入网页或日志。模型请求由 worker 发起：Jev 只发送可见文字；启用图片识别后看图还会发送受限微博 CDN 配图链接。均不发送 Cookie、登录态或整页 HTML。

默认本地反馈只含哈希、微博标识、原判断、版本和标签；提前开启采样后才保存可见正文，未保存的文字不能离页后恢复。反馈不自动上传，不自动改 prompt、阈值或规则，也不永久改变相似微博的判断。

改进流程为：采样与标注 → 导出 → 人工分析 → 更新规则 → 回归验证 → 发布新版。

缓存须按内容、图片、模型、服务地址、策略、字段版本和设置隔离。错误不写成功缓存；设置变化取消迟到结果。清缓存不清反馈。默认缓存 30 天、上限约 5,000 条。

## 7. 评估与验收

已实现并通过当前回归：安装构建、四账号共同规则及原账号策略、三态与 Shadow、手动反馈、SPA/动态卡片处理、响应校验、缓存/密钥边界、超时重试、导出与评估工具。日常 Chrome 的 Jev 连通及页面标签已验证。

尚需完成：

- 图片通道真实效果检查，包括纯风景、高尔夫、图表、混合图片和无法读取的图片。
- 100–200 条真实人工标注，至少三个独立浏览会话，覆盖四账号、转发、投资保护、体育、人物、中文反讽与图片边界。
- 留出未参与调参的样本；不同规则版本和文字/图片模型分批核验。
- 误折叠率 ≤ 2%、折叠精确率 ≥ 90%；同时报告噪音召回、延迟及账单成本。无折叠预测或无人工标注不能算达标。
- 一周实际阅读体验验收。

模型连通、代码回归通过和真实分类质量是不同的验收结果。评估报告不会自动切换 Active。
