# 微博语义过滤扩展：使用与维护

更新：2026-09-22。当前交付为 **Chrome 插件 0.3.3**，在微博原网页显示建议、灰化或折叠。用户已安装并接通 Vercel Jev；真实分类效果仍需持续人工评估。

## 安装与更新

- [扩展源码与开发说明](../../extensions/weibo-semantic-filter/README.md)
- 加载目录：`extensions/weibo-semantic-filter/dist/`
- 安装包：`extensions/weibo-semantic-filter/artifacts/weibo-semantic-filter-0.3.3.zip`

首次安装：Chrome 打开 `chrome://extensions` → 开启「开发者模式」→「加载已解压的扩展程序」→ 选择包含 `manifest.json` 的 `dist` 文件夹。

更新：构建完成后，在上述管理页找到「微博语义过滤」，点击重新加载，再刷新微博。无需卸载或重填 key；已打开的设置页也应刷新。构建新文件不等于 Chrome 已自动加载新版。

打开设置：工具栏拼图 →「微博语义过滤」→「设置」；或扩展详情页的 **Extension options / 扩展程序选项**。API key 填在插件自己的「模型连接」里。

## Vercel Jev 连接

| 设置项 | 值 |
| --- | --- |
| API 地址 | `https://ai-gateway.vercel.sh/typesafe/v1/systemone` |
| 模型名称 | `typesafe-ai/jev` |
| API key | 自己的 Vercel AI Gateway key |

填写后勾选「启用语义判断」→「保存设置」→ 授权模型域名 →「测试已保存的连接」。输入框留空表示保留已有 key。测试成功只证明固定文字请求可通，不证明所有规则效果已达标，也不测试图片通道。

`network` 表示请求未正常完成；`auth` 表示认证或服务权限问题。连接测试会提供可用的 HTTP 状态和服务端错误信息。不要把 key 发进聊天或写进源码；先根据具体错误检查 API 地址、模型、Gateway key 和服务端账户状态。

## 自动折叠其他账号

默认开启「自动折叠四个目标账号之外的微博」。在支持的信息流中，可靠识别到其他发帖账号时，直接显示「已折叠：非目标账号，自动折叠」，Shadow 下也生效，不等待、不调用 AI，也不计入「建议折叠」数量。可通过设置页「阅读方式」单独关闭。

按最外层发帖账号判断，四个目标账号转发别人的内容不会因此被当作推荐博主折叠；即使关闭某个目标账号的语义过滤，它也仍属于四个目标账号。作者或卡片结构无法可靠识别的特殊广告暂保持原样。「展开」「本页全部展开」和关闭过滤仍优先。

## 当前四账号规则

共同规则默认开启，适用于但斌、王文（股道热肠也）、韩广斌和老曾阿牛：

- **林园、董宝珍**：正文或转发原文明确出现姓名（含繁体）就建议折叠；本地判断，无模型费用。只出现在图片里的姓名暂不识别。
- **体育**：篮球、足球、高尔夫、赛事、运动员、个人打球等，文字语义高置信命中时建议折叠。
- **纯风景／无字体育照片**：需要单独开启图片识别，详情见下节。

未命中共同规则时，但斌过滤可靠识别的纯互动回复，王文过滤无具体信息的哲理、鸡汤、诗词；韩广斌和老曾阿牛保留。四个目标账号中已关闭过滤的账号不处理；其他可识别账号由上述自动折叠规则处理。不主动抓取历史内容或展开全文；多数规则遇到正文截断、上下文不足会保留，明确人物命中例外。

原来的价值投资、媒体保护不覆盖用户明确要求的人物或体育过滤。规则优先级与阈值见[架构](../architecture/weibo-semantic-filter-mvp.md)。

## 图片识别

设置 →「四个账号的通用规则」→ 勾选「启用图片识别」→ 保存，同时保持「启用语义判断」。图片识别默认关闭，使用同一 Vercel key 调用 `google/gemini-2.5-flash-lite`，另计用量；发送候选微博的可见文字及微博 CDN 配图链接。

仅对没有实质文字的完整配图看图，一次最多 9 张。纯风景、明确打高尔夫等体育照片可命中；混合内容、财报图表、文字截图、图片不完整或看不清时保留。不识别视频。当前实现和模拟测试不能替代真实图片效果评估。

## 如何看到效果

支持微博首页、分组页和账号主页。正常浏览、滚动即可处理接近视口的卡片；评论区、详情页、搜索和热榜暂不支持。

- **观察 Shadow**：四个目标账号显示「建议折叠／建议灰化」，不自动隐藏其正文；其他账号按独立开关直接折叠。
- **自动 Active**：实际折叠或灰化；随时点「展开」。
- 插件启用且本页未暂停时，每张卡片都显示状态：等待处理、正在判断、保留、建议折叠或已折叠。识别或连接失败会说明原因并暂时保留；点击插件「重新扫描」或刷新微博可重试。
- 「显示判断详情（调试）」只控制技术详情，关闭后仍显示结果与纠错按钮。无附言的转发同样会识别并读取原文。
- Popup 查看识别数、完成数、建议数；「语义服务已配置」只说明配置存在。需要验证连接时到设置页测试。
- 「本页全部展开」会暂停本路由后续展示变化；点「恢复本页过滤」才继续。重新扫描本身不解除暂停。

## 反馈是否会学习

**不会自动学习或改规则。**「应保留」立即展开，「应折叠」立即折叠，Shadow 也适用；同时保存本地反馈并显示「已记录」。手动选择在当前标签页会话有效，刷新后重新按规则判断。保存失败会提示重试，页面展示操作仍生效。

默认保存内容哈希、微博标识、原判断、规则版本和标签。只有提前勾选「保存目标账号的可见原文」后才保存正文；未保存的正文离页后无法凭哈希恢复。反馈不会自动发送给 Jev，也不会自动发送给开发助手。

改进流程：开启采样并收集有代表性的误判 → 导出反馈与样本 → 人工分析 → 修改规则 → 回归测试 → 更新插件。也可以直接描述新的规则需求。清除分类缓存不会删除反馈；删除本地反馈需单独操作。

## 开发与验证

从仓库根目录运行：

```sh
npm --prefix extensions/weibo-semantic-filter ci
npm run weibo:check
npm run weibo:test
npm run weibo:build
npm run weibo:package
npm run weibo:evaluate -- /absolute/path/to/weibo-feedback.json
```

真实浏览器回归方法见[开发说明](../../extensions/weibo-semantic-filter/README.md)。当前有 39 项扩展自动测试、15 项独立 Chrome 检查和 30 条匿名 DOM fixture；浏览器报告与截图在 `artifacts/`，不随安装包发布。用户 Jev 连接与页面标签已验证，100–200 条真实中文标注、图片效果和一周日用验收尚未完成。

旧抓取任务、独立阅读器及相应命令已移除，不要再运行旧 `weibo:fetch`、`weibo:web`、`weibo:daemon`。历史数据库仍保留，详情见[退役记录](../migrations/weibo-pilot/retirement-2026-09-21.md)。
